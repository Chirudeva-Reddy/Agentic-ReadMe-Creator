How it works

Facts first, prose second

Most README generators start by writing. This one starts by measuring what's true about the code, then only lets the README say that.

01 · ground

Record the facts

Collects the tests, reads the license and config, runs the CLI's --help. Writes facts.json.

02 · you

Edit one line

Rewrite the hook in story.yaml as the problem a stranger recognises.

03 · produce

Write the README

README, light and dark diagrams, and a video storyboard, all built from those two files.

04 · verify

Check every claim

Badges, numbers, and links are checked against facts.json. Exits 1 on a lie.

05 · launch

Render the video

An AI agent renders the storyboard with /brag. It becomes the README's top image.

Case study

csv-dedupe: from a bare repo to a launch-ready README

A small Python tool that removes duplicate rows from CSV exports. It had working code, 4 tests, and sample data, but no README. Here's every step, with the real output from each command.

After · what a visitor sees now
  1. 1

    Ground: record what's true agentic-readme ground .

    Before writing a word, the tool reads the project and saves 9 facts, each with the file it came from. Everything written later has to match these.

    $ agentic-readme ground .
# absolute paths shortened
[Phase 0: GROUND] Analyzing repository at …/csv-dedupe...
✔ Locked contracts created:
  - Story Spec: .agentic-readme/story.yaml
  - Facts Ledger: .agentic-readme/facts.json (9 facts recorded)
    // facts.json (excerpt)
test_count       4            ← tests/
license          "MIT"        ← LICENSE
python_version   ">=3.9"      ← pyproject.toml
python_loc       60           ← .

                  [-o OUTPUT] path"   ← cli.py
  2. 2

    You: rewrite the hook story.yaml, one line

    The default hook is just the package description. It's accurate, but nobody stops scrolling for it. This is the only manual step, and it matters most: name the problem a stranger already has. The new line comes from the repo's own sample data (data/contacts.csv really does list Ana three times).

    - hook: Removes duplicate rows from CSV exports, optionally matching on one column.
+ hook: Your customer export lists Ana three times.

    Produce: write the README agentic-readme produce .

    Every asset is built from the two locked files. Nothing new is invented at this stage. Until a real video exists, the top image is a drawn terminal preview, and the README says so instead of passing it off as a recording.

    $ agentic-readme produce .

    Verify: and try to make it lie agentic-readme verify . / audit

    The first check passes. Then we edit the tests badge from 4 to 40 and run the read-only audit. It fails with exit code 1, so a CI job would block that pull request.

    $ agentic-readme verify .
[Phase 2: VERIFY] Running cross-asset verification & claim auditing...
✔ Verification PASSED (23 facts checked, 0 fatal bugs)

    Launch: render the video Claude Code + /brag

    produce also wrote a problem-first storyboard: hook → reveal → real run → proof → how to get it. The agent rendered it with /brag, running the real command and copying its actual output. Then produce ran again and swapped the drawn preview for the video on its own. Verify: 23 facts, 0 errors.

What we fixed

Running it on real repos made it better

Before the case study, we ran the tool on three small sample projects and read every line it wrote. Each problem below turned up that way, was fixed, and now has a test so it can't come back.

46 → 52
tests in the suite
3
worked examples: Python, Node, and csv-dedupe
0
errors or warnings on every example
20s
launch video, rendered from a storyboard

The tagline was nonsense

It pasted the package description into a canned template.

Tired of opaque estimates and manual bottlenecks in a tiny cli that splits a restaurant bill fairly, tip included?
A tiny CLI that splits a restaurant bill fairly, tip included.

Diagrams made up a domain

Any data/ folder was labelled with a leftover from another project.

The auto-fixer broke the license badge

Its pattern swallowed the badge color, which left a broken image.

img.shields.io/badge/license-MIT?style=flat-square
img.shields.io/badge/license-MIT-blue?style=flat-square

Node projects had their tests miscounted

It counted test files, not test cases.

tests · 1 passed (habit-streak has 2 tests in 1 file)
tests · 2 passed

Evidence links pointed at folders that didn't exist

Line counts always cited src/, and test counts always cited tests/.

habit-streak: 0 fatal errors, 2 warnings (badge → tests/, which doesn't exist)
habit-streak: 0 fatal errors, 0 warnings

There was no actual video

It stopped at a storyboard file, and nothing embedded a video.

brag_spec.json only; README top image: drawn SVG
Skill Phase 3 renders it with /brag; produce embeds the GIF, linked to the MP4
What it still can't do
  • The CLI alone can't render video. That step needs an AI agent with /brag, Node 22+, and ffmpeg. Without them you get the storyboard and the labelled drawing.
  • The auditor assumes every number in a README describes the repo itself, so a README that quotes another project's numbers can trip it.
  • The "real run" command is guessed from the entrypoint, so the agent has to add realistic arguments.
